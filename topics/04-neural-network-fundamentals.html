Neural Network Fundamentals

The chain rule, applied a few million times through a computational graph, is the entire training algorithm underneath every model on this site — and the specific choices layered on top of it (activations, init, normalization, residuals) are the difference between a network that trains and one that doesn't.

Know cold ~24 min · prerequisites: chain rule, gradient descent (01)
TL;DR

A neural network is alternating linear transformations and non-linear activations; backpropagation trains it by running the chain rule backward through the computational graph exactly once, so every weight — no matter how deep — gets its gradient in a single backward pass. Everything else in this page is engineering built on top of that one algorithm: which non-linearity to use (ReLU/GELU/SiLU), how to initialize weights so signals don't vanish or blow up before training even starts (Xavier/He), how to keep activations well-scaled mid-training (BatchNorm/LayerNorm/RMSNorm), and how to let gradients skip past dozens of layers undamaged (residual connections). One sentence for an interview: backprop is the chain rule, applied systematically to a computational graph, computing every parameter's gradient in one backward traversal.

01Where this sits in the timeline

Every architecture covered elsewhere on this site — CNNs, RNNs, Transformers — is just a different way of arranging the same underlying machinery described on this page. That machinery had to be invented first, and it very nearly wasn't.

Before

Rosenblatt's perceptron (1958) — a single linear layer plus a threshold — could learn simple linearly separable patterns. Minsky & Papert's 1969 book Perceptrons proved it mathematically could not learn XOR, a trivially simple function. Funding and interest collapsed; this is a large part of what caused the first AI winter. Nobody had an efficient way to train networks with hidden layers, which is what XOR actually requires.

→
Innovation

Rumelhart, Hinton & Williams, "Learning representations by back-propagating errors" (Nature, 1986), popularized backpropagation: a way to compute the gradient of a loss with respect to every weight in a multi-layer network using one forward pass and one backward pass, by repeated application of the chain rule. Stacking hidden layers — the exact thing that was impossible to train before — suddenly became tractable.

→
After

Everything since has been architecture design on top of the same training algorithm: CNNs (LeCun, late 1980s–1998) for grid-structured data, RNNs/LSTMs for sequences, and eventually Transformers (2017). The layers changed. The way you train them — backprop, chain rule, gradient descent — has not.

02The intuition, before any math

Backpropagation answers one question, asked for every weight, at every step of training: how much is this specific weight to blame for the error?

A forward pass through a network is a long chain of simple, differentiable steps — multiply by a weight matrix, add a bias, squash through a non-linearity, repeat. Feed in an input, and every layer transforms it a little until you get a prediction. Compare that prediction to the true answer and you get one number: the loss, "you were this wrong." Computing that number was never the hard part. The hard part is credit assignment — figuring out, for a weight sitting three layers deep inside the network, exactly which direction and by how much it should move to make that one number smaller next time. Doing this by brute force — nudge one weight, rerun the entire forward pass, see what changed, repeat for every weight — is computationally hopeless for a network with millions of parameters.

The trick is noticing that a forward pass is a computational graph: a directed sequence of differentiable operations, where every node's output feeds the next node's input. The chain rule says the derivative of the final loss with respect to any node in that graph is the product of the local derivatives along the path from that node to the loss. Because many paths share sub-paths (a weight in layer 1 affects the loss only through everything downstream of it), you can compute every weight's gradient with a single backward traversal of the graph, reusing intermediate results instead of recomputing anything — that reuse is the entire reason backprop is efficient instead of exponential.

Concretely: a 2-layer network is $x \to$ linear + activation $\to h \to$ linear + activation $\to \hat y \to$ loss $L$. To find $\partial L / \partial W^{[1]}$ — the gradient for the first layer's weights, farthest from the loss — you don't analyze layer 1 in isolation. You take the gradient signal that already arrived at the hidden layer (computed while working out layer 2's gradient a moment ago) and multiply by one more local derivative. Gradients flow backward like water through a pipe network, picking up a multiplicative factor at every junction they pass through. That's also exactly why they can shrink toward zero or blow up over many junctions — more on that in Tradeoffs.

03Architecture: forward pass, then backward pass through the same graph

A multilayer perceptron (MLP) is nothing more than this pattern, stacked: linear transformation → non-linear activation, repeated. The universal approximation theorem (Cybenko, 1989; Hornik, 1991) says that a single hidden layer, given enough neurons and a non-linear activation, can approximate any continuous function on a compact input domain to arbitrary precision. It's important to be precise about what that theorem does and doesn't promise: it's an existence proof, not a training recipe. It says nothing about how many neurons "enough" actually is (it can be exponentially many) or whether gradient descent will ever find those weights. In practice, depth matters even though the theorem only requires width — a deep network can represent the same function with far fewer total neurons than a shallow one, because each layer composes on the features the previous layer already built (edges → textures → parts → objects), instead of trying to represent the whole function flat in one layer.

Forward pass (blue) and backward pass (pink) through the same tiny network
Forward (blue): each node computes a value from the ones behind it, left to right, ending in the loss $L$. Backward (pink, running on the same wires): starting from $L$, each node receives a gradient from downstream and multiplies it by its own local derivative before passing it further back. Every weight on every wire gets exactly the product of the local derivatives on the path from that weight to $L$ — nothing more, nothing less.

Real networks almost never stack raw linear+activation layers indefinitely — past a modest depth, plain stacking becomes very hard to optimize (see Why, next). The fix that made 50-, 100-, even 1000-layer networks trainable is the residual block: normalize, transform, and add the result back onto a running "residual stream" instead of overwriting it — the exact same idea, in the exact same shape, as the residual stream running through every Transformer block (08).

A generic pre-norm residual block — the residual stream flowing bottom to top
Each sub-layer reads the current value off the residual stream (dashed line), computes an update, and adds it back rather than replacing it. If the update is close to zero — a not-yet-useful or poorly initialized transformation early in training — the identity path still carries the input straight through undamaged. That direct additive path is also a direct additive path for gradients flowing backward: they don't have to survive being multiplied through every transformation, they can just flow along the stream. Same mechanism as the residual stream in a Transformer block (08), because it's the same underlying fix.

Shapes and cost, concretely. A linear layer maps (batch, in_features) → (batch, out_features) via a weight matrix of shape (in_features, out_features) plus a bias — that's in_features × out_features + out_features parameters, full stop, regardless of batch size. A useful rule of thumb from the scaling-law literature: total training compute is roughly $6 \times N \times D$, where $N$ is parameter count and $D$ is the number of training tokens seen — a forward pass costs about $2N$ FLOPs (one multiply and one add per parameter), and the backward pass costs roughly twice the forward pass again, since it has to propagate gradients with respect to both the weights and the activations. Parameters set your memory floor for weights; activations you must keep around for the backward pass set a second, often larger, memory cost that scales with batch size and depth — which is precisely why gradient accumulation and activation checkpointing exist (more in Applications and in 23).

04The equations, term by term

Backprop through a 2-layer MLP

$$\begin{aligned}z^{[1]} &= W^{[1]}x + b^{[1]}, \qquad a^{[1]} = f(z^{[1]}) \\ z^{[2]} &= W^{[2]}a^{[1]} + b^{[2]}, \qquad \hat y = g(z^{[2]}) \\ L &= \text{loss}(\hat y, y)\end{aligned}$$

That's the forward pass. The backward pass computes a gradient $\delta$ at each layer's pre-activation, propagates it back through one linear map, and stops:

$$\delta^{[2]} = \frac{\partial L}{\partial z^{[2]}} = \frac{\partial L}{\partial \hat y}\odot g'(z^{[2]}), \qquad \frac{\partial L}{\partial W^{[2]}} = \delta^{[2]}\left(a^{[1]}\right)^{\top}, \qquad \frac{\partial L}{\partial b^{[2]}} = \delta^{[2]}$$
$$\delta^{[1]} = \left(\left(W^{[2]}\right)^{\top}\delta^{[2]}\right)\odot f'(z^{[1]}), \qquad \frac{\partial L}{\partial W^{[1]}} = \delta^{[1]}x^{\top}, \qquad \frac{\partial L}{\partial b^{[1]}} = \delta^{[1]}$$
  • δ the "error signal" arriving at a layer's pre-activation — everything the loss cares about that flows through this point, collapsed into one vector.
  • f', g' the local derivative of that layer's own activation function, evaluated at the value it output on the forward pass. This is why the forward pass's intermediate values have to be cached — the backward pass needs them.
  • (W^[2])ᵀδ^[2] how the error signal at layer 2 propagates back through layer 2's weights to become "blame" felt by layer 1's output — this is the literal mechanism of credit assignment.
  • δ(a)ᵀ an outer product: every weight $W_{ij}$ gets the product of "how wrong was output $i$" and "how active was input $j$" — a weight only gets blamed in proportion to how much it was actually used.
Derivation Deriving backpropagation from the chain rule alone

Those four equations were stated, not earned. Here is where each one comes from. Nothing below is more than the chain rule applied carefully, which is the point: backprop is not a separate algorithm you have to memorise.

  1. $$\delta^{[l]} \;\equiv\; \frac{\partial L}{\partial z^{[l]}}$$
    Why define this at all: we want $\partial L / \partial W^{[l]}$, not $\partial L / \partial z^{[l]}$. But every parameter in layer $l$ influences the loss only by changing $z^{[l]}$. So if we know how sensitive $L$ is to $z^{[l]}$, one more short step gives us every gradient in that layer. $\delta$ is the quantity worth computing.
  2. $$\delta^{[2]} = \frac{\partial L}{\partial \hat y} \odot g'(z^{[2]})$$
    Why the Hadamard product: the output activation acts elementwise, so $\hat y_i$ depends on $z^{[2]}_i$ and on no other component. The chain rule for a single index reads $\partial L/\partial z_i = (\partial L / \partial \hat y_i)\, g'(z_i)$. Stack those independent scalar equations and you get an elementwise product, not a matrix multiply.
  3. $$\frac{\partial L}{\partial z^{[1]}_j} = \sum_i \frac{\partial L}{\partial z^{[2]}_i}\cdot\frac{\partial z^{[2]}_i}{\partial z^{[1]}_j}$$
    Why a sum: this is the multivariable chain rule. Perturbing $z^{[1]}_j$ changes $a^{[1]}_j$, which feeds into every unit of the next layer. The blame arriving at one hidden unit is the total collected over all the paths leaving it.
  4. $$\frac{\partial z^{[2]}_i}{\partial z^{[1]}_j} = W^{[2]}_{ij}\, f'(z^{[1]}_j)$$
    Why: expand the single path. $z^{[2]}_i = \sum_j W^{[2]}_{ij} a^{[1]}_j + b^{[2]}_i$ and $a^{[1]}_j = f(z^{[1]}_j)$. Differentiating the composition gives the weight on that edge times the local activation slope.
  5. $$\begin{aligned}\frac{\partial L}{\partial z^{[1]}_j} &= f'(z^{[1]}_j)\sum_i W^{[2]}_{ij}\,\delta^{[2]}_i \\[6pt] \delta^{[1]} &= \left(\left(W^{[2]}\right)^{\top}\delta^{[2]}\right)\odot f'(z^{[1]})\end{aligned}$$
    Why the transpose appears, concretely: in that sum, $i$ is the row index of $W^{[2]}$ and $j$ is fixed as the column. Summing down a column of $W$ is the same as summing across a row of $W^{\top}$. The forward pass used row $i$ to build output $i$ from all inputs. The backward pass reads column $j$ to collect what input $j$ is answerable for. Same matrix, read the other way.
  6. $$\frac{\partial L}{\partial W^{[2]}_{ij}} = \delta^{[2]}_i\, a^{[1]}_j \;\;\Longrightarrow\;\; \frac{\partial L}{\partial W^{[2]}} = \delta^{[2]}\left(a^{[1]}\right)^{\top}$$
    Why the outer product: $W^{[2]}_{ij}$ appears in exactly one place in the whole forward pass, the expression for $z^{[2]}_i$, where it multiplies $a^{[1]}_j$. So its derivative is that single term, with no sum. Every $(i,j)$ pairing of the two vectors is an outer product.
  7. $$\frac{\partial L}{\partial b^{[2]}} = \delta^{[2]}$$
    Why it is just $\delta$: $\partial z^{[2]}_i / \partial b^{[2]}_i = 1$. The bias enters additively, so the error signal passes through it unchanged.
What this actually tells you. There is no backpropagation algorithm in the sense of a clever new idea. There is the chain rule, plus one observation: $\delta^{[l]}$ is a shared subexpression. Every parameter in a layer needs it, and every layer below needs it too. Compute it once per layer, cache it, reuse it. The naive alternative recomputes that same downstream product separately for each parameter, so cost scales with the number of parameters instead of staying at roughly one extra pass. That reuse is the entire reason a billion-parameter network is trainable at all.

Normalization

BatchNorm computes statistics per feature, across the batch:

$$\begin{aligned}\mu_B &= \frac{1}{m}\sum_{i=1}^{m} x_i, \qquad \sigma_B^2 = \frac{1}{m}\sum_{i=1}^{m}(x_i-\mu_B)^2 \\[4pt] \hat x_i &= \frac{x_i - \mu_B}{\sqrt{\sigma_B^2+\epsilon}}, \qquad y_i = \gamma\hat x_i + \beta\end{aligned}$$

LayerNorm uses the identical formula — but $\mu$ and $\sigma^2$ are computed per example, across that example's own features, never touching the batch dimension at all. RMSNorm goes one step further and drops the mean-centering entirely, normalizing only by the root-mean-square magnitude:

$$\text{RMS}(x) = \sqrt{\frac{1}{d}\sum_{j=1}^{d}x_j^2 + \epsilon}, \qquad y = \gamma \odot \frac{x}{\text{RMS}(x)}$$

No batch statistics, no running mean, and (in the original formulation) no bias term or mean subtraction — cheaper to compute than LayerNorm, and empirically about as effective, which is why it's the default in most modern LLMs.

05Why these specific choices, not the obvious alternatives

Why ReLU beat sigmoid/tanh. Sigmoid and tanh squash their input into a bounded range, which means for large positive or negative inputs the function is nearly flat — its derivative is close to zero. Chain a dozen of those together and the gradient reaching early layers is a product of a dozen near-zero numbers: it vanishes, and early layers stop learning almost entirely. ReLU, $f(z)=\max(0,z)$, has a derivative of exactly 1 for any positive input — no saturation, no shrinkage, gradients pass straight through unchanged wherever the unit is active. That's the whole reason it unlocked meaningfully deeper networks. It's not free: for negative inputs, ReLU's derivative is exactly 0, so a unit that ends up permanently negative on every training example stops receiving any gradient and "dies." LeakyReLU (small non-zero slope for negative inputs) and GELU/SiLU (smooth, non-zero gradient almost everywhere) exist specifically to patch that failure mode while keeping ReLU's core advantage.

Why GELU/SiLU in modern transformers instead of plain ReLU. GELU is $x\cdot\Phi(x)$ and SiLU (Swish) is $x\cdot\sigma(x)$ — both multiply the input by a smooth gate that's close to 0 for very negative inputs and close to 1 for very positive ones, but unlike ReLU the transition is smooth and the function dips slightly negative just below zero rather than clamping hard at exactly zero. That smoothness gives better-behaved gradients during optimization at the scale transformers are trained at, and empirically these activations outperform ReLU in that regime — which is why BERT, GPT-family models, and most modern transformer feed-forward blocks default to GELU or a gated SiLU variant (SwiGLU) rather than plain ReLU.

Why residual connections instead of just building a deeper plain network. He et al. (2015) showed something that looks paradoxical at first: a plain (non-residual) 56-layer network had higher training error than an 18-layer one — not just worse test error from overfitting, worse error on the data it was trained on. A deeper plain network is strictly more expressive (it could always learn to reproduce the shallow one by setting extra layers to the identity), so this is an optimization failure, not a capacity failure — plain SGD simply struggles to find that identity mapping across many stacked non-linear layers. A residual block computes $f(x)+x$ instead of $f(x)$, so the identity mapping is the default whenever $f$ contributes little — the network doesn't have to learn identity, it starts there and only has to learn a useful deviation from it. That's why residual connections, not just "more layers," are what actually unlocked networks past ~20 layers.

06Normalization tradeoffs and what actually breaks

The choice of what to normalize over — batch, features, or a group of channels — is not a stylistic detail, it's the answer to a very common interview trap question: why do transformers use LayerNorm/RMSNorm and not BatchNorm?

Normalizes overone feature/channel, across the batchall features, within one exampleall features, within one example (no centering)a group of channels, within one example

The trap-question answer: BatchNorm's statistics are computed across examples in the batch, which means the normalization applied to one example literally depends on which other examples happen to be sitting in the same batch — fine for image classifiers where batch size is typically large and fixed, badly broken for sequence models where batch size varies, sequences are padded to different lengths, and — critically — autoregressive generation happens one token at a time with an effective batch dimension that doesn't resemble training at all. LayerNorm and RMSNorm normalize within a single example's own feature vector, so the computation is identical whether batch size is 512 or 1, and identical between training and inference. That independence from batch size and sequence length is the entire reason sequence models standardized on per-example normalization.

Failure modes that actually show up

  • Dead ReLUs. A unit whose pre-activation is negative for every input in the training set receives zero gradient forever — a large learning-rate spike or an unlucky initialization can push a unit there and it never recovers. Symptoms: a growing fraction of activations reading exactly zero. Fixes: lower learning rate, He initialization, LeakyReLU/GELU/SiLU instead of plain ReLU.
  • Vanishing / exploding gradients in RNNs. An RNN reuses the same weight matrix at every timestep, so the gradient flowing back through $T$ timesteps is (roughly) that matrix raised to the $T$-th power. If its dominant eigenvalue is below 1, the gradient shrinks toward zero over long sequences; above 1, it grows exponentially and can produce a NaN loss within a few hundred steps.
  • Gradient clipping exists specifically for the exploding side: cap the global gradient norm at a threshold before the optimizer step, which caps the update magnitude without changing its direction. It's a cheap, standard fix (Pascanu et al., 2013) and is still routinely used when training any recurrent or otherwise deep, unstable model.
  • Exploding logits. Unnormalized final-layer logits that grow very large before the softmax push cross-entropy toward numerical overflow and make the loss landscape near that point extremely sharp — handled in practice with the log-sum-exp trick for numerical stability, and in some modern LLMs with an explicit logit soft-cap.
Common misconception

"A deeper network takes proportionally longer to train per step because backprop has more layers to work through." The backward pass costs roughly a fixed multiple of the forward pass (about 2×) regardless of how that compute is distributed across layers — depth alone doesn't change that ratio. What depth does cost is memory: every layer's activations from the forward pass have to be kept around until the backward pass needs them, so memory (not per-step compute overhead) is usually the first thing that breaks as you add layers — which is exactly why activation checkpointing and gradient accumulation exist.

2026 status

RMSNorm paired with a SwiGLU-style gated feed-forward block has become the default recipe across most frontier open-weight LLM families (LLaMA, Mistral, Qwen, and others), having largely displaced the original 2017 Transformer's LayerNorm + ReLU/GELU feed-forward design. The training algorithm underneath all of it is still exactly the backprop described in this page, essentially unchanged since 1986 — the architecture keeps evolving, the gradient computation doesn't.

07Worked example and a production use case

Tiny worked example — one backward pass, by hand

Illustrative / toy numbers only. Chain: input $x \to$ neuron 1 (ReLU) $\to h \to$ neuron 2 (sigmoid) $\to \hat y \to$ MSE loss against target $y=1.0$.

Forward: $x=1.0$, $w_1=0.8,\ b_1=-0.2 \Rightarrow z_1 = 0.8(1.0)-0.2 = 0.6 \Rightarrow h=\text{ReLU}(0.6)=0.6$. $w_2=0.5,\ b_2=0.1 \Rightarrow z_2 = 0.5(0.6)+0.1 = 0.4 \Rightarrow \hat y = \sigma(0.4) \approx 0.599$. Loss $L=\tfrac{1}{2}(\hat y-y)^2 \approx \tfrac{1}{2}(-0.401)^2 \approx 0.080$.

Backward: $\partial L/\partial \hat y = \hat y - y \approx -0.401$. $\partial \hat y/\partial z_2 = \hat y(1-\hat y) \approx 0.240$, so $\delta_2 = -0.401 \times 0.240 \approx -0.096$. That gives $\partial L/\partial w_2 = \delta_2 \cdot h \approx -0.096 \times 0.6 \approx -0.058$ and $\partial L/\partial b_2 = \delta_2 \approx -0.096$. Propagate one layer further back: $\partial L/\partial h = \delta_2 \cdot w_2 \approx -0.048$, and since $z_1=0.6>0$ the ReLU derivative is exactly 1, so $\delta_1 \approx -0.048$ passes through completely unchanged — giving $\partial L/\partial w_1 = \delta_1 \cdot x \approx -0.048$ and $\partial L/\partial b_1 \approx -0.048$. Notice the pattern: every gradient further back is just the previous one, multiplied by one more local derivative. That's the whole algorithm, run by hand, twice.

Production use case: training a 7B-parameter model on limited GPU memory

Two of the tradeoffs above compound directly into a real constraint: a 7B-parameter model's weights, gradients, and optimizer state already consume tens of gigabytes in FP32, before a single activation is stored. Mixed precision stores most of the forward/backward computation in FP16 or BF16 — half the memory, and much higher throughput on GPU tensor cores — while keeping a master copy of the weights in FP32 so small updates don't get lost to rounding, with loss scaling (more important for FP16's narrow exponent range than BF16's) to stop small gradients from underflowing to zero. Gradient accumulation handles the batch-size side of the same problem: if the batch size you want doesn't fit in memory, run several smaller micro-batches forward and backward, summing their gradients, and only take one optimizer step after accumulating enough of them — mathematically close to training at the larger batch size, at the cost of extra forward/backward passes instead of extra memory. Combined with gradient clipping to keep the (mixed-precision, accumulated) updates numerically stable, this is the standard recipe that lets a handful of memory-constrained GPUs train a model that would otherwise need far more hardware. The rest of that toolbox — sharding, offloading, activation checkpointing — gets a full treatment in 23.

08Interview questions

BeginnerWalk me through backpropagation for a simple 2-layer network.

Run the forward pass, caching every intermediate value: $z^{[1]}=W^{[1]}x+b^{[1]}$, $a^{[1]}=f(z^{[1]})$, $z^{[2]}=W^{[2]}a^{[1]}+b^{[2]}$, $\hat y=g(z^{[2]})$, then the loss. Going backward, compute $\delta^{[2]}=\partial L/\partial \hat y \odot g'(z^{[2]})$, use it to get $\partial L/\partial W^{[2]} = \delta^{[2]}(a^{[1]})^\top$, then propagate one layer further with $\delta^{[1]} = (W^{[2]\top}\delta^{[2]})\odot f'(z^{[1]})$ to get $\partial L/\partial W^{[1]}$. Each layer's gradient reuses the layer above it's already-computed signal, multiplied by one local derivative.

BeginnerWhy did ReLU replace sigmoid/tanh as the default activation?

Sigmoid and tanh saturate — for large-magnitude inputs their derivative approaches zero. Chained across many layers, that near-zero derivative gets multiplied together and the gradient reaching early layers vanishes, so those layers barely learn. ReLU's derivative is exactly 1 for any positive input, so gradients pass through unshrunk wherever the unit is active. The tradeoff is dead units: a unit stuck permanently negative gets exactly zero gradient and stops updating, which is what LeakyReLU/GELU/SiLU are designed to fix.

IntermediateWhat's the difference between BatchNorm and LayerNorm, and why do transformers use LayerNorm (or RMSNorm) instead of BatchNorm?

BatchNorm normalizes one feature's values across all examples in the batch; LayerNorm normalizes all of one example's features against each other, never touching the batch dimension. BatchNorm's statistics therefore depend on batch composition and size, need running estimates carried into inference, and break down at small or variable batch sizes. Sequence models have variable-length, often padded sequences and generate one token at a time at inference — batch statistics are unreliable or simply don't make sense there. LayerNorm and RMSNorm normalize per example, so they're identical regardless of batch size or between training and inference, which is why they're the standard for transformers and RNNs.

IntermediateWhy do residual connections make very deep networks trainable?

He et al. showed that plain (non-residual) deep networks can have higher training error than shallower ones — an optimization failure, since a deeper network could always represent the shallow function by learning identity in the extra layers, it just struggles to find that solution via SGD. A residual block computes $f(x)+x$ instead of $f(x)$, so identity is the default whenever the learned branch contributes little, and gradients get a direct additive path backward through the residual stream instead of having to survive being multiplied through every intervening non-linear transformation.

IntermediateXavier/Glorot vs. He initialization — what's the actual difference, and why does it matter?

Both scale the initial random weights so that activation variance stays roughly constant from layer to layer instead of shrinking or blowing up as depth increases. Xavier/Glorot initialization assumes a roughly linear, symmetric activation like tanh/sigmoid and scales variance by $1/\text{fan}_{avg}$. He initialization accounts for ReLU zeroing out roughly half of all pre-activations, so it scales variance by $2/\text{fan}_{in}$ to compensate for that lost variance. Using the wrong one for your activation function reintroduces exactly the vanishing/exploding signal problem initialization is supposed to prevent, just starting at step zero instead of building up over training.

DeepYou're training a 7B-parameter model and keep running out of GPU memory. What levers do you pull, and why?

Mixed precision (FP16/BF16 compute with an FP32 master copy of weights) roughly halves memory and increases tensor-core throughput. Gradient accumulation lets you simulate a larger batch size than fits in memory by summing gradients over several forward/backward micro-batches before one optimizer step. Gradient clipping keeps the resulting updates numerically stable under mixed precision. If that's still not enough, the next lever is activation checkpointing (recompute activations during the backward pass instead of storing all of them) and optimizer/parameter sharding — both covered in depth in 23. None of these change what backprop computes, they change how much of it you have to hold in memory at once.

DeepYour RNN's training loss suddenly goes to NaN a few hundred steps in. What's happening, and what do you do?

Classic exploding gradient: an RNN reuses the same weight matrix at every timestep, so the backward gradient is roughly that matrix raised to the power of the sequence length. If its dominant eigenvalue is above 1, the gradient — and eventually the loss — grows exponentially with sequence length until it overflows to NaN. Fix: clip the global gradient norm to a fixed threshold before the optimizer step (this caps magnitude without changing direction), consider a lower learning rate, and if this keeps recurring, consider whether the architecture itself (e.g. gated recurrence, or dropping recurrence for attention) is fighting you rather than a tuning issue.
